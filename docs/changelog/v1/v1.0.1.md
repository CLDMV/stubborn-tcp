# StubbornTCP v1.0.1 Changelog

**Release Date**: October 2025
**Release Type**: Patch

---

## Overview

Fixes the CommonJS entry point so `require()` returns the constructor directly, and replaces the test scripts.

---

## 💥 Breaking Changes

### `require()` returns the constructor instead of a Promise

Despite being a patch, this changes what CommonJS code receives. In v1.0.0, `index.cjs` exported a Promise (and a `StubbornTCP` property that was a second Promise) resolving to the constructor. It now loads the ES module synchronously through `createRequire` and exports the constructor itself, with `StubbornTCP` and `default` as aliases:

```javascript
const StubbornTCP = require("@cldmv/stubborn-tcp");
// or: const { StubbornTCP } = require("@cldmv/stubborn-tcp");
const client = new StubbornTCP({ host: "localhost", port: 8080 });
```

Loading an ES module synchronously relies on Node.js's `require(esm)` support (Node.js ^20.19.0 or >=22.12.0); on older versions, use `import()`.

## Upgrade notes

- CommonJS code that did `await require("@cldmv/stubborn-tcp")` should drop the `await` and use the returned constructor directly. ESM code is unaffected.
