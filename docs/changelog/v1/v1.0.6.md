# StubbornTCP v1.0.6 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.0.6`

---

## Overview

This release puts the package's Node.js requirement back where the code actually needs it. v1.0.5 set `engines.node` to `>=22.22.0`, but that number was the floor of the build and test toolchain, not of the client. `engines.node` is now `>=14.0.0` again, the bundle is built for Node.js 14, and the toolchain floor moves to npm's `devEngines`, which only applies when you work on this package itself.

The client's behaviour is unchanged. The only source edit is the Node.js version named in the CommonJS entry's `require()` error message.

---

## 📦 Requirements

### `engines.node` is the runtime floor again ([#37](https://github.com/CLDMV/stubborn-tcp/pull/37))

- **`import`** works on Node.js 14.0.0 or newer. The package has no runtime dependencies and uses only the `net`, `tls` and `events` built-ins, and `engines.node` goes from `>=22.22.0` back to `>=14.0.0`. A TCP connect, write and echo round trip from the packed tarball was checked on Node.js 14.0.0 and 16.12.0.
- **`require()`** needs Node.js `^20.19.0` or `>=22.13.0`, because the CommonJS entry loads the ES module build through `require(esm)`. On older versions it throws `ERR_REQUIRE_ESM`, and the message now reads `require() needs Node.js ^20.19.0 or >=22.13.0` and still points to `import()`.
- **Development** needs Node.js 22.22.0 or newer (Vitest 5 and tsup 9). That floor now lives in `devEngines.runtime` with `onFail: "error"`, which npm checks only for this project's own `npm install`, `npm ci` and `npm run`, never for consumers.

---

## 📦 Packaging

- `dist/index.mjs` is built with esbuild's `node14` target instead of `node22`, so the bundle runs on the versions `engines` names ([#37](https://github.com/CLDMV/stubborn-tcp/pull/37)).

## 🔧 CI & tooling

- The CI and publish workflows keep `min_node_version` at 22.22.0, and their input descriptions and comments now say it is the dev toolchain floor that must match `devEngines`, not `engines` ([#39](https://github.com/CLDMV/stubborn-tcp/pull/39)).

## Upgrade notes

- No breaking changes and no API changes; drop-in for v1.0.5.
- If you held back on v1.0.4 because of v1.0.5's Node.js 22.22.0 floor, this version installs on Node.js 14 and newer again. Use `import` below Node.js 20.19.0; `require()` needs `^20.19.0` or `>=22.13.0`.
