# StubbornTCP v1.0.5 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.0.5`

---

## Overview

This release raises the supported Node.js version to 22.22.0 or newer and republishes the TypeScript declarations with the full instance API. The client's runtime behaviour is unchanged: the source edits are a renamed CommonJS entry file, a rewritten (equivalent) export statement, and the new version in the `require()` error message.

The Node.js floor is a real requirement change even though this ships as a patch. `engines.node` goes from `>=14.0.0` to `>=22.22.0`, and the bundle is now built for Node.js 22. Read the upgrade notes before updating on an older runtime.

---

## 💥 Breaking Changes

### Node.js 22.22.0 or newer is required ([#32](https://github.com/CLDMV/stubborn-tcp/pull/32), fixes [#31](https://github.com/CLDMV/stubborn-tcp/issues/31))

`engines.node` was `>=14.0.0`, and `require()` additionally needed Node.js `^20.19.0` or `>=22.12.0` for `require(esm)`. Both are now `>=22.22.0`, despite this being a patch release. The development toolchain (chokidar 6, tsup 9) needs Node.js 22.22, so nothing older can be built or tested any more, and the published floor now says so instead of promising versions that were never exercised.

- `dist/index.mjs` is now built with esbuild's `node22` target instead of `node14`, so the bundle no longer lowers syntax for older runtimes.
- The CommonJS entry's `ERR_REQUIRE_ESM` message now reads `require() needs Node.js >=22.22.0` and still points to `import()`.
- The CI test matrix starts at Node.js 22.22.0 instead of 22.12.0.

## 🐛 Bug Fixes

### TypeScript declarations describe the instance API ([#34](https://github.com/CLDMV/stubborn-tcp/pull/34))

v1.0.4's declarations were emitted by TypeScript 7, whose JavaScript declaration emit is still incomplete: `StubbornTCP` was declared as a bare function with `prototype: any`, so TypeScript code saw none of the instance members. TypeScript is now pinned to 6 and the declarations were regenerated. `types/src/stubborn-tcp.d.mts` now declares `StubbornTCP` as a class with its constructor options and members, including `open()`, `close()`, `write()`, `setIdleTimeout()`, the heartbeat helpers and the TLS helpers, alongside the existing callable signature.

The source export was rewritten from `export default StubbornTCP` plus `export { StubbornTCP }` to a single `export { StubbornTCP, StubbornTCP as default }`, so the emitted declarations export the class after declaring it (TypeScript 6 had hoisted the default export above the declaration, which CodeQL flags as use before declaration). The runtime exports are the same: the default export and the named `StubbornTCP` export, and `require()` still returns the constructor with `StubbornTCP` and `default` aliases.

## 📦 Packaging

- **CommonJS entry renamed in source.** `src/cjs-shim.cjs` is now `src/index.cjs`, next to the ESM entry `src/index.mjs`, so source and build share entry names ([#32](https://github.com/CLDMV/stubborn-tcp/pull/32), fixes [#30](https://github.com/CLDMV/stubborn-tcp/issues/30)). The published file is still `dist/index.cjs`, copied in verbatim by the tsup build, so nothing changes for consumers.
- **Development export condition.** The `stubborn-tcp-dev` condition's `require` target now points at `src/index.cjs`. The Vitest configuration and the `node --test` CommonJS run both resolve the package through this condition, so the tests exercise `src/` ([#32](https://github.com/CLDMV/stubborn-tcp/pull/32)).

## Upgrade notes

- **Node.js 22.22.0 or newer is now required.** On an older runtime, npm warns with `EBADENGINE` (or refuses the install under `engine-strict`), and the package is no longer built or tested there. Stay on v1.0.4 until you can upgrade Node.js.
- No API changes. The default and named `StubbornTCP` exports and the `require()` shape are the same as v1.0.4.
- TypeScript users now get the instance members typed. Code that relied on them being `any` may see new type errors where calls don't match the documented signatures.
