# StubbornTCP v1.0.4 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/1.0.4`

---

## Overview

This release makes TLS connections work for the first time, fixes the CommonJS entry for bundlers, and moves the package to a built `dist/` layout with TypeScript declarations. The client's API and behavior are otherwise unchanged, but the published files are different, so read the packaging notes below if you reach into the package or bundle it.

The repository also moves to the CLDMV v4 release flow with a vitest test suite, linting, formatting and file headers ([#1](https://github.com/CLDMV/stubborn-tcp/pull/1)).

---

## 🐛 Bug Fixes

### TLS connections work ([#1](https://github.com/CLDMV/stubborn-tcp/pull/1))

Inside the constructor, the destructured `tls` option (a boolean) shadowed the imported `tls` module, so every TLS connection attempt called `true.connect(...)` and threw `TypeError: tls.connect is not a function` — from `open()`, or from the constructor when `host` and `port` were supplied. The module is now imported under a different name. Code passing `tls: true` now connects over TLS instead of throwing; `secureConnect`, `keylog`, `OCSPResponse` and the TLS helper methods work as documented.

### `require()` works in bundles and fails clearly on older Node.js ([#1](https://github.com/CLDMV/stubborn-tcp/pull/1))

The CommonJS entry loaded the ES module through `createRequire(__filename)`, which esbuild and webpack cannot follow. It is now a small hand-written wrapper that uses a plain `require("./index.mjs")`. The CommonJS entry has always depended on Node.js's synchronous `require(esm)`; on versions without it, `require()` now throws an `ERR_REQUIRE_ESM` error that names the supported versions (`^20.19.0` or `>=22.12.0`) and points to `import()`, instead of a bare loader error. `require()` still returns the constructor, with `StubbornTCP` and `default` aliases.

## 📦 Packaging

The import surface is the same — the package root, with a default export plus `StubbornTCP` — but the published files changed:

- **Built output.** The code now ships as `dist/index.mjs`, a single minified bundle of `src/` (function names kept), and `dist/index.cjs`, the ~1 kB CommonJS wrapper. The root-level `index.mjs`, `index.cjs` and `stubborn-tcp.mjs` files are gone. `exports` only ever exposed the package root, so this matters only to tools that bypass `exports` and load files by path; `main` and `module` now point into `dist/`. Stack traces point into the minified bundle.
- **Smaller tarball.** `files` now ships only `dist/` (without source maps), `types/`, the README and the license. `test/` and `examples/` are no longer published; the usage examples remain in the [repository](https://github.com/CLDMV/stubborn-tcp/blob/master/examples/usage-examples.md). The unpacked size drops from about 100 kB to about 45 kB.
- **TypeScript declarations.** Generated `.d.mts` declarations are now published (`types/`, wired through `types` and the `types` export condition). TypeScript projects that previously treated the package as untyped will now type-check against these declarations.
- **Development export condition.** A `stubborn-tcp-dev` export condition resolves to the unbuilt `src/` files; it only takes effect when a consumer opts into that condition.
- `publishConfig.access` is now `public` (v1.0.3 declared `restricted`).

## 🔧 CI & tooling

- Added the full CLDMV v4 workflow set (release flow, CI, CodeQL, Scorecard, dependency review, bundle size, coverage badge) and Dependabot configuration.
- Tests moved to `@cldmv/vitest-runner` (`tests/*.test.vitest.mjs`): the old integration and timeout scripts were ported to run against local servers on `127.0.0.1` with no network access, and characterization tests cover the rest of the API, including TLS over a pre-shared key. The CommonJS entry is tested with `node:test` against the built `dist/`.
- Added the fleet ESLint and Prettier configuration, a check-only pre-commit hook, and `@cldmv/fix-headers` with refreshed file headers.

## ⚠️ Known issues

- Calling `open()` on a client that is already connected ends with `connectState` `0`: the replaced socket's late `close` event still fires after the new connection is set up. The test suite pins this behavior; it is not fixed in this release. Calling `open()` with no arguments clears the stored host and port and throws `ERR_MISSING_ARGS`; pass `host` and `port` either to the constructor or to `open()`, not neither.

## Upgrade notes

- No API changes — drop-in for v1.0.3 when you import the package root.
- If you deep-import or bundle files by path (`stubborn-tcp.mjs`, `index.cjs`, `test/`, `examples/`), switch to the package root.
- If you pass `tls: true`, connections now actually use TLS; check your `tlsOptions` (certificates, `servername`, `rejectUnauthorized`).
